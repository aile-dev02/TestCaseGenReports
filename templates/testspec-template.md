# テンプレートの使い方

## ファイル配置

このファイルを `master/specs/` に配置してください。

```
master/specs/
  ├── project-A.md     # テスト仕様書（案件ごとに1ファイル）
  └── project-B.md
```

## フィールド説明

### メタデータ（先頭テーブル）

| 項目 | 必須 | 説明 |
|:-----|:----:|:-----|
| `案件タイプ` | ✅ | 新規開発 / 機能追加 / リニューアル のいずれか |
| `上流ファイル（主）` | 任意 | 詳細設計書のファイルパスまたは URL |
| `上流ファイル（副）` | 任意 | 基本設計書など補足資料のパス |
| `作成日` | ✅ | YYYY-MM-DD 形式 |
| `顧客` | 任意 | 顧客名 |
| `自社担当` | 任意 | 担当者名 |
| `バージョン` | ✅ | 例: `0.1（草案）`、`1.0（確定）` |

### セクション 1.1 上流設計書との対応

- **上流ID**: `DD-NNN` 形式（例: `DD-001`）
- **展開先TC-ID**: カンマ区切りで複数指定可（例: `TC-001, TC-002, TC-003`）

### セクション 3 テストケーステーブル

| 列 | 必須 | 説明 |
|:---|:----:|:-----|
| `TC-ID` | ✅ | `TC-NNN` 形式（例: `TC-001`）。仕様書内で一意であること |
| `テスト名` | ✅ | `正常系：`, `異常系：`, `境界値：` などのプレフィックスを推奨 |
| `種別` | ✅ | `画面`, `I/F`, `バッチ`, `API` など |
| `優先度` | 任意 | `高` / `中` / `低`。Failサマリーの優先度別集計に使用 |
| `手順` | ✅ | テスト手順。セル内改行可（次行に続けて記述） |
| `期待結果` | ✅ | 期待される動作・出力 |
| `上流ID` | 推奨 | `DD-NNN` 形式。1.1 の上流IDと一致させること |
| `備考` | 任意 | メモ・注意事項 |
| `担当者` | 任意 | テスト実施者名 |
| `完了日時` | 任意 | テスト完了日時（例: `2026-06-02 14:30`） |
| `実行ステータス` | 任意 | `PASS` / `FAIL` / `NA` / `NOT_EXECUTED` / `WAITING` / `SKIP`（省略時は `NOT_EXECUTED`） |

## バリデーション

`npm run validate` を実行すると以下をチェックします:
- メタデータ必須フィールド（案件タイプ / 作成日 / バージョン）
- `TC-ID` が `TC-NNN` 形式であること
- `TC-ID` の重複がないこと
- 手順・期待結果が空でないこと
- `上流ID` が `DD-NNN` 形式であること（記載した場合）
